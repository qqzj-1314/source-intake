## 实际页面流程

Windows 本机 Chrome，通过 Playwright CLI 操作真实面板及 MCP 处理器的隔离 Harness，材料均为合成输入：

- 代码包含可执行 HTML 片段，预览逐字符一致且没有执行；关闭预览不修改来源。
- paste 数据中先放文本格式，再放图片，验证使用图片数据而非“第一项”。测试同一次粘贴包含多张图片，也测试快速连续两个独立 paste 事件；两张图片内容不同，分别显示缩略图并正确预览。
- 已输入的代码草稿保持不变；图片支持适应窗口、原始尺寸、滚动查看与关闭，390 像素宽度下页面不横向溢出，Esc 可关闭。
- 人工延迟前一次图片响应，关闭后重新打开同一项；旧响应不会覆盖新预览。
- 预览导入计划后再次打开内容预览，导入仍可执行。实际写入一份代码和两张不同截图，逐文件 SHA256 与输入一致，图片没有被复用成第一张。
- SVG 图片粘贴被拒绝，队列仍能处理后续输入；PNG 签名但损坏的文件在查看时显示“无法预览图片”，不持续显示加载状态。

上述粘贴用浏览器 DataTransfer/ClipboardEvent 注入合成数据，验证页面事件处理与真实 MCP 保存流程，不声称已在每个操作系统的实际剪贴板、每种宿主 iframe 中完成 Ctrl+V 实测。宿主若不传图片数据，可使用选择附件或原有截图入口。JPEG/GIF/WebP/BMP 有签名识别测试，本轮实际页面图片解码主要覆盖 PNG。
