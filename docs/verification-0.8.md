## 独立浏览器与实际保存

通过 Playwright CLI 在真实 Chrome 中操作隔离 Harness，使用合成需求与材料，验证：

- 查询和选择均不覆盖当前需求，也不使已有预览失效；显式带入才填写字段、标记 BOS 来源并使旧预览失效。
- 补充修改说明原文、3 个源码和 2 个附件均保留。实际导入后逐文件原始字节一致，需求快照保存 BOS 来源与操作时间，修改说明原文一致。
- 修改需求编号或主动切换为手工时，清除原 BOS 来源与操作时间；当前内容保留。
- 空结果不修改当前需求。取消等待的提示说明上游可能仍在执行；人为延迟旧响应后重新查询，旧结果未覆盖新结果。
- 返回标题中的 HTML 片段按文字显示。桌面及 390 像素宽度界面可用，无横向溢出；截图已查看。

默认 Harness 的 BOS 数据为合成记录，不使用生产凭据，也不放宽临时演示目录的写入限制。

## 部署边界

本机插件注册更新至 0.8.0，使用当前项目中的面板服务及 Python 内核。独立新进程可验证版本与 BOS 工具；运行中的 Codex 可能继续使用旧进程，需要重启应用后重新打开插件。本轮未重启当前应用，不能将 Chrome Harness 验收等同于更新后的 Codex 内嵌界面实测。

功能只读，不修改 BOS 状态，也不自动下载 BOS 附件或执行导入的业务源码。
