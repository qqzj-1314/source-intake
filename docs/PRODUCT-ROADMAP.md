# 产品迭代目标与交付记录

本轮持续迭代窗口：2026-11-25 晚至 2026-11-26 08:00，Asia/Hong_Kong。
目标是同一份本地需求和源码能在 Codex、Claude Code、Qoder、Trae、WorkBuddy 之间接续使用。

## 产品判断

用户的核心任务是把分散材料整理成 AI 能直接执行的需求上下文。编辑器插件只是入口。产品应有独立内核、标准 MCP、可搬迁 Skill 和清晰的材料目录；Codex 面板是可选交互层。

优先解决三种摩擦：换工具必须重做导入、AI 漏读后加材料、用户无法判断安装或执行是否成功。

## 按价值排序的计划

| 优先级 | 改进 | 用户价值 | 验收依据 |
| --- | --- | --- | --- |
| P0 | 通用 stdio MCP：预览、导入、历史、需求上下文、健康检查 | 无需 Codex 也能完成核心流程 | 真实 MCP 黑盒测试与原生客户端连接/调用证据 |
| P0 | 各客户端配置导出、可迁移 Skill、Claude 原生插件目录 | 降低安装门槛 | 配置解析、路径重生成、插件校验；宿主实测单独标注 |
| P0 | 当前需求上下文聚合 | 换 AI 时不漏补充说明和后来添加的材料 | 原文、附件递归枚举、链接边界与只读测试 |
| P1 | 已有需求索引、搜索和“继续这个需求”入口 | 需求积累后仍能快速定位 | 多需求目录、重名编号、手工添加与缺失材料场景 |
| P1 | 明确的工作状态、验收标准与交接记录 | 区分材料导入和业务实现完成 | 状态转换、历史留存、无误覆盖 |
| P1 | 新手安装向导与更完整 doctor | 尽早定位 Python/Node/权限/连接问题 | 缺依赖、无效路径、只读目录、真实宿主差异 |
| P1 | 持续集成及 Windows/Linux/macOS 证据 | 广泛分发有可验证的基础 | 实际 CI 结果；不把单机测试当跨平台证明 |
| P2 | 项目目录规则模板与材料检查 | 减少重复设置与遗漏 | 模板导入导出、空材料提示、旧版本兼容 |
| 待接口 | BOS 查询和需求快照刷新 | 减少手填需求信息 | 真实 MCP 合约和认证可用后接入，不模拟已联通 |

不通过新增无关功能填满时间；每轮都应对应具体用户摩擦、有适当测试并同步 Git。

## 执行与恢复

- Qoder 只接边界清晰的小任务；主代理独立审查和集成。
- 每个发行版本在 CHANGELOG 记录用户可见变化，保留 Git 提交与兼容性证据。
- 后续聊天或额度恢复时，先检查当前 Git、未完成工单和本计划，再继续下一项。
- 额度耗尽时保留进度；重置后的自动唤醒取决于宿主目标执行器，不视为插件自身能力。
- 08:00 到期时进行最终核对和交付汇总，不在到期后继续新增范围。
